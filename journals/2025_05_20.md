- Linux 文件 IO #Linux
	- 系统调用 `read`、`write`
		- ```c
		  // POSIX.1 
		  ssize_t read(int fd, void *buf, size_t len);
		  ```
		- ```c
		  ssize_t write(int fd, const void *buf, size_t count);
		  ```
	- `read`、`write`这类系统调用对应有一个 buf 参数，执行的时候内核会将 buf 对应的内容读、写到内核的 cache 中。然后函数执行就直接返回了。
	- 内核缓冲
		- 由于 CPU 和 disk 之间速度差异很大，如果每次 read、write 都需要等待 disk 落盘再返回就太慢了。所以在文件系统中就实现了一个 Page Cache，每次 read、write 的操作都是只对这个 Cache 进行操作。就返回了，实际的缓存如何同步到 disk 就是交给文件系统实现的。那么缓存策略有以下的几种：
			- read ahead（空间局部性）
				- 做 disk io 的时候，预先多读一些数据出来放到 cache 中。*在顺序 IO 中比较有效*
			- write back
				- write 直接写 cache。文件系统做脏页管理，写入重排序、批量写入等操作。
		- page cache
			- 时间局部性 —— 刚刚被访问过的数据，很有可能会被再次访问。
			- 空间局部性 —— 数据会被连续访问
	- ## user-buffered IO
		- 在文件系统中，最小的 IO 单位是 block，所有的读、写操作都是以 block 进行的。但是在应用开发中不会有 block 的概念，高级语言中更多的是 `string`、`object`或者是以 byte 为单位读写的。如果每次 IO 都是使用`read`、`write`这样的系统调用，虽然有内核 cache 做优化，但是频繁的在**用户态**与**内核态**之间切换也会带来消耗。
		- 这个问题的核心就是`read`、`write`参数中 buff size 大小设置不合理。因为系统调用是按照 block 为单位进行 IO 的，但是应用程序则不会以 block 为单位来 IO。为了解决这个问题，就引入用户空间的 buffer，每次的 IO 都只是在用户空间 buffer 进行。从而减少 read、write 的调用。
